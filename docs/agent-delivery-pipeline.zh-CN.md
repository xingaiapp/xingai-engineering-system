# Agent 交付流水线

[English](agent-delivery-pipeline.md)

一套可复用的做法:一个调度员加一队专家 agent,从想法一路推进到上线,中间设两道人工关卡。适用于 Claude Code 子 agent(`.claude/agents/*.md`)加斜杠命令,思路同样适用于 Cursor Task agent。

## 结构

```text
你 ──► /ship "<目标>" ──► 调度员(主会话)
                            │ 每个阶段并行派出专家
                            ▼
 0 立项 → 1 研究 → 2 评估 → ★3 确认 → 4 编码
      → 5 测试 → 6 修复回路 → 7 发布前审查 → ★8 确认发布
      → 9 部署与验证 → 10 复盘
```

子 agent 不能再派子 agent,所以调度员必须以主会话身份运行(`claude --agent <调度员>`,或用斜杠命令让主会话扮演它)。

## 角色

| 角色 | 职责 | 能改代码 |
|---|---|---|
| 调度员 | 拆任务、派发、把结论合并成 P0/P1/P2 清单 | 否 |
| 研究员 | 市场/竞品/可行性,事实与推断分开 | 否 |
| UX 专家 | 首屏、流程、移动端、状态、跨站一致性 | 否 |
| SEO / AEO / GEO | 元数据、结构化数据、sitemap、`llms.txt`、AI 爬虫策略 | 否 |
| 安全与隐私 | 响应头、密钥、政策与实际行为是否一致、公开前扫描 | 否 |
| 多语言与无障碍 | 翻译完整度、对比度、键盘、读屏 | 否 |
| 增长分析 | 漏斗、渠道、实验 | 否 |
| 领域合规 | 例如金融内容"研究背景而非建议"检查 | 否 |
| 功能开发 | 只按已确认的 spec 实现 | 是 |
| Bug 负责人 | 复现 → 根因 → 最小修复 + 回归测试 | 是 |
| 性能负责人 | 先测 → 修一个瓶颈 → 复测 | 是 |
| 测试负责人 | 跑测试/构建,核对验收标准与回归 | 否 |
| DevOps | 经命令行 agent 提交推送,再交给验证 | 仅 git |
| 运维监控 | 线上可用性、线上是否=HEAD、缓存新鲜度 | 否 |

## 阶段约定

每个阶段写一个文件到运行目录(`pipeline/runs/<日期>-<slug>/NN-名称.md`),下一阶段只读上一阶段的产出。

| # | 阶段 | 通过条件 |
|---|---|---|
| 0 | 立项 | 目标、范围、不做什么、成功指标写在一页 |
| 1 | 研究 | 每条结论有来源;事实与推断分开 |
| 2 | 评估 | 价值/成本/风险;推荐方案与被否决方案 |
| ★3 | 确认 | 固化 spec:范围、验收标准、文件、回滚方案 |
| 4 | 编码 | 只改 spec 范围内文件;给出改动文件清单 |
| 5 | 测试 | 测试、类型、构建通过;每条验收标准有证据 |
| 6 | 修复回路 | 失败项修好重测;**最多 3 轮**,超过则停下报告 |
| 7 | 审查 | 无密钥、无领域合规越界、性能不退化 |
| ★8 | 确认发布 | 批准发布 |
| 9 | 部署与验证 | 已推送;线上=HEAD;关键页面正常;知道如何回滚 |
| 10 | 复盘 | 一周后对照立项时的指标 |

## 自主权模型

范围明确、可回滚的常规改动,可以不逐次询问就通过关卡 3 和 8,前提是汇报里写明做了什么。以下情况永远需要人明确决定:

- force push 或改写历史
- 删除文件、分支、数据
- 推送公开仓库
- 密钥、环境变量、部署或 CI 配置
- 数据库与生产数据
- 决策引擎字段,或 worker 与 API 的边界
- 他人未提交的改动
- 花钱或对外发送内容

## 实践中有用的护栏

- **审计 agent 只读。** 审计者只出报告,只有开发负责人改代码,结论更诚实,diff 也更小。
- **已验证 vs 推断。** 每条发现都标注;没查的放进"未覆盖"。
- **只暂存自己的文件。** 共享工作区里不用 `git add -A`;断言失败就中止后面的步骤。
- **公开仓库关卡。** 审计结果含未修复的弱点,应放在私有位置,只公开方法。
- **命令行 agent 的信任。** 登录与工作区信任确认必须由人完成,不要脚本绕过。
- **超时。** 无界面的命令行 agent 遇到范围太大的问题会卡住;限定到单个仓库、小任务,并放宽超时。

## 最小配置

```text
.claude/
  agents/<调度员>.md       # tools: Agent, Read, Grep, Glob, Bash, WebFetch, WebSearch
  agents/<专家>.md         # 每人一个文件;审计者只给只读工具
  commands/ship.md         # 让主会话扮演调度员并执行各阶段
  PIPELINE.md              # 上面的阶段表与自主权模型
```

站点与仓库的对应关系、私有仓库名只保留在你自己的私有工作区副本里,不要放进共享模板。
