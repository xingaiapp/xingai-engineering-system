# Product Upgrade Rule

XingAI products should improve by inheritance, not replacement.

> 不是重做新产品，而是在前一版上升级。

## Rule

Every later version must preserve:

- established visual language
- product identity
- navigation model
- primary user flow
- core user-facing features

Then add new capabilities as optional entries, modes, pages, panels, or workflows.

## Formula

```text
V2 = visual alignment with V1 + functional inheritance from V1 + V2 additions
V3 = visual alignment with V1 + functional inheritance from V2 + V3 additions
V4 = visual alignment with V1 + functional inheritance from V3 + V4 additions
```

## Do

- Keep the original main use case as the default path.
- Keep familiar navigation and interaction patterns.
- Add advanced features as optional paths.
- Use product-facing words, not internal roadmap labels.

## Do Not

- Start from a blank new UI.
- Replace the main flow with a generic dashboard.
- Remove familiar features from the previous version.
- Expose V1/V2/V3 labels in user-facing UI.
- Make users relearn the product after each version.

## Why It Works

Users trust continuity. A later version should feel like the same product gaining useful new powers, not a different product.
